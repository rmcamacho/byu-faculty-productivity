# ECEn 240/301 Op-Amp Course Exercise

> **SANITIZED FACULTY-TUTORIAL COPY — NOT THE LIVE COURSE**

This packet is adapted from Ryan Camacho's current combined ECEn 240/301 course. It contains no student records, live Learning Suite identifiers, restricted solution-manual content, or links to private course files. The lecture summary and practice problems are original workshop adaptations of the course's operational-amplifier unit.

The authoritative course source is a native Google Slides lecture linked from Learning Suite. The PDF used in class is only an export of that deck. Participants do not need access to either source because the relevant concepts are summarized here.

The facilitator may also use the native deck for a short Google Slides connector demonstration. Participants can perform the same workflow with their own synthetic test deck or a nonsensitive lecture deck. Complete `docs/GOOGLE_DRIVE_CONNECTOR_SETUP.md` before the Slides exercise. Any demonstration edit must be made to a duplicate—not the live course deck. See `tutorial_materials/facilitator/google_slides_connector_demo.md`.

## Scenario

You have inherited a small set of course-design files for the op-amp unit. Use Codex as a colleague: ask it to inspect the whole folder, cite evidence, propose improvements, and create a draft only after you approve a plan.

## Exercise A — Apply Elder Gong's Address

The timestamped Elder Gong notes are included in this folder so the exercise is self-contained. Prompt:

```text
Read every file in this folder, including elder_gong_2026_timestamped_notes.md. Propose three concrete changes to this unit that would prepare students to work responsibly with AI while preserving productive struggle, human judgment, and evidence of individual learning. For each change, identify the learning outcome, what AI may do, what the student must do, how learning will be verified, and the smallest feasible pilot. Cite the source files. Do not modify anything yet.
```

Follow up with:

```text
Turn the strongest idea into a one-page implementation plan. Include instructions students would see, an instructor check, and a brief explanation of how the activity supports agency, dignity, and durable learning. Save it as proposed_ai_activity.md in this folder, but do not alter the source files.
```

## Exercise B — Develop Additional Homework

Start a fresh Codex conversation with only this folder in scope, then prompt:

```text
Review the learning outcomes, lecture summary, current practice set, draft solutions, constraints, and synthetic student feedback. First audit the existing materials for conceptual mistakes, ambiguity, uncovered outcomes, and likely student misconceptions. Then propose two original op-amp homework problems at the same level that improve the coverage. Do not copy textbook problems and do not edit files yet. Show all calculations and flag any assumption that fails because of output saturation.
```

After reviewing the proposal:

```text
Create proposed_additional_problems.md with polished student-facing problems followed by an instructor solution key. Make the problems self-contained and accessible without a circuit diagram. Include a short verification checklist for the instructor. Leave all existing files unchanged.
```

## Optional Exercise C — Google Slides Connector

After completing `docs/GOOGLE_DRIVE_CONNECTOR_SETUP.md`, use either your synthetic verification deck or a lecture deck that contains no student information:

```text
Use the Google Drive connector to inspect this complete native Google Slides deck: [paste your Google Slides URL]. Identify the instructional sequence, concepts emphasized, worked examples, and places where a student misconception is addressed or left unaddressed. Cite slide numbers or titles. Do not edit the presentation.
```

Then ask Codex to propose one new slide. Require it to explain where the slide belongs, which existing slide should serve as the visual exemplar, and why the addition supports a specific learning outcome. If you decide to create it, instruct Codex to copy the deck first and edit only the copy.

Never connect Codex to a deck containing student names, grades, accommodations, private comments, or other student records unless that use is institutionally approved.

## What Good Codex Use Looks Like

- Define the source folder and intended audience.
- Ask for citations to filenames and sections.
- Separate inspection, proposal, and file-writing stages.
- Require calculations and physical operating-region checks.
- Review the result as the responsible instructor.
- Make a copy before demonstrating edits to a live cloud document.
- Never point a public demo at a live course folder containing student data.
